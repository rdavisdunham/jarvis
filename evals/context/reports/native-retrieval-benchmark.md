## Cost per query

Database time only here. In production each `context_search` adds one query embedding (`text-embedding-3-small`, about 4 tokens for these queries): roughly $0.0000001 at an assumed $0.02 per million tokens, recorded under cost feature `context_embeddings`. No other model call is made before synthesis.

## Recommendation

**HNSW recommendation: not needed.** Exact cosine scan meets the gate at corpus size (worst p95 160 ms < 2,000 ms); keep it and rerun this benchmark before adding an index. With HNSW indexes present the planner still chose the exact plan for every configuration: the semantic leg orders by `distance, id`, which an HNSW index cannot serve, and the owner and lifecycle filters leave few enough rows that a sort is cheap. An index-friendly leg (distance only, index forced) would take the bare semantic leg from p95 12.0 ms to 4.7 ms at recall@100 98.1%; revisit when the exact leg approaches the budget, and then drop the `id` tie-break from the ORDER BY (keep it only as a post-sort).
